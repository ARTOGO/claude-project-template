# Init Command

> AI 引導式專案初始化。分析需求、智慧推薦技術棧、自動產出完整配置。

## 使用方式

```bash
/project:init
```

---

## 核心原則

### 1. 需求優先，動態調整

根據用戶描述的需求，動態決定要問哪些問題：
- LINE Bot 專案 → 不問前端框架
- 純 API 服務 → 不問 UI 框架
- 用戶說「不確定」→ AI 分析後推薦，而非直接寫入「不確定」

### 2. Quick Start vs 進階模式

- **Quick Start**：AI 根據需求自動推薦所有設定，用戶只需確認
- **進階模式**：逐步讓用戶選擇，但仍有 AI 推薦的預設值

### 3. 用戶輸入必須反映在輸出

- 需求描述 → 寫入 PRD.md 的「產品概述」
- 技術選擇 → 寫入 project.yaml（不能有「不確定」等無效值）

```text

請問您想如何提供專案需求？

A. 📄 讀取現有文件
   我會讀取您的 PRD、README 或其他文件來理解需求

B. ✏️  現在描述
   直接告訴我您想做什麼，我會幫您分析
```

## Step 2: AI 分析需求

根據收集到的需求，AI 進行分析：

```text
┌─────────────────────────────────────────────────────────────────────────────────┐
│                         AI 需求分析                                              │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                  │
│  輸入：用戶的需求描述                                                            │
│                                                                                  │
│  分析項目：                                                                      │
│                                                                                  │
│  1. 專案類型判斷                                                                 │
│     • LINE Bot → backend-only（不需要前端）                                      │
│     • Web 平台 → web-app（前後端）                                               │
│     • API 服務 → backend-only                                                    │
│     • 管理後台 → web-app 或 frontend-only                                        │
│                                                                                  │
│  2. 技術棧推薦                                                                   │
│     • 根據專案類型、規模、團隊經驗推薦                                           │
│     • 考量因素：開發速度、維護性、生態系                                         │
│                                                                                  │
│  3. 需要詢問的問題                                                               │
│     • 只問「必要且無法推斷」的問題                                               │
│     • LINE Bot 不問前端框架                                                      │
│     • 純前端不問後端語言                                                         │
│                                                                                  │
│  輸出：分析報告                                                                  │
│                                                                                  │
└─────────────────────────────────────────────────────────────────────────────────┘
```

### 分析報告範例

```text
🤖 Claude: 我分析了您的需求，以下是我的理解：

## 📋 專案概要

| 項目 | 分析結果 |
|------|---------|
| 專案類型 | 純後端服務（LINE Bot） |
| 核心功能 | 支出記錄、報表產生 |
| 目標用戶 | 個人用戶 |
| 預估規模 | 小型專案 |

## 🛠️ 推薦技術棧

| 項目 | 推薦 | 原因 |
|------|------|------|
| 後端語言 | Node.js (TypeScript) | LINE SDK 支援完整、開發快速 |
| 框架 | Express | 輕量、適合 Bot 專案 |
| 資料庫 | SQLite | 小型專案足夠、免設定 |
| 部署 | Vercel | 免費額度、簡單部署 |

## ❓ 需要確認

由於這是 LINE Bot 專案，以下項目**不需要**設定：
- ~~前端框架~~
- ~~UI 框架~~
- ~~Package Manager（後端用 npm 即可）~~

這樣分析正確嗎？
```

### 處理「不確定」的輸入

**當用戶回答「不確定」、「不知道」、「都可以」時：**

```text
用戶：不確定要用什麼資料庫

🤖 Claude: 沒問題！根據您的專案需求（小型 LINE Bot），我推薦：

**SQLite** - 原因：
• 免設定，直接使用檔案儲存
• 小型專案完全足夠
• 未來需要時可輕鬆遷移到 PostgreSQL

我會採用 SQLite，您之後隨時可以在 project.yaml 修改。

（不會在 project.yaml 寫入「不確定」）
```

### PRD.md 產出範例

**重要**：PRD 必須包含用戶的實際需求描述，不是空白模板

```markdown
# 產品需求文件 (PRD)

> expense-line-bot - LINE Bot 記帳助手

## 1. 產品概述

### 1.1 背景

用戶需要一個方便的方式來記錄日常支出，透過 LINE 這個最常用的通訊軟體，
可以隨時隨地快速記帳，不需要另外下載 App。

### 1.2 目標

建立一個 LINE Bot，讓用戶可以：
- 透過對話記錄每日支出
- 自動分類支出項目
- 月底產生支出報表

### 1.3 目標用戶

- 個人用戶
- 想要簡單記帳但不想用複雜 App 的人
- 習慣使用 LINE 的用戶

## 2. 功能需求

### F1.1 支出記錄

**描述**: 用戶透過 LINE 訊息記錄支出

**用戶故事**:
作為用戶，我希望直接在 LINE 輸入「午餐 120」就能記錄支出，以便快速記帳

**驗收標準**:
- [ ] 支援格式：「項目 金額」
- [ ] 自動辨識支出類別
- [ ] 記錄成功後回覆確認訊息

### F1.2 月報產生

**描述**: 月底自動產生支出報表

**用戶故事**:
作為用戶，我希望每月收到支出統計，以便了解消費狀況

**驗收標準**:
- [ ] 每月 1 日自動發送上月報表
- [ ] 包含分類統計
- [ ] 可手動觸發「本月報表」
```

## 協作模式設定

### Subagent（預設）

不需額外設定，直接使用。

適用：
- 一般開發流程
- 快速 Review
- 成本考量

### Agent Teams（實驗性）

需要在 `.claude/settings.json` 啟用：

```json
{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}
```

適用：
- 複雜架構決策
- 需要多方討論的 Review
- 大型重構

在 `project.yaml` 記錄選擇：

```yaml
team:
  collaboration_mode: "agent-teams"
```
